# Synapse Clinical Dashboard

Vite + React + TypeScript dashboard mirroring live Firestore sessions from the iOS/Watch stack.

**Product / architecture / agent rules:** [`../docs/MASTER.md`](../docs/MASTER.md) (canonical). Native agents should not own this tree unless asked.

## Quick start

```bash
cd web
cp .env.example .env   # project synapse-clinical-hz
npm install && npm run dev   # http://localhost:5173
npm run build                # tsc -b && vite build
```

## Routes

| Route | Shows |
| --- | --- |
| `/` | `VITE_DEFAULT_SESSION_ID`, live from Firestore (falls back to the canned Focus demo after 4 s) |
| `/session/:sessionId` | Any session id, live |
| `/demo/focus` · `/demo/vision` · `/demo/kinetic` | Canned snapshot, no network — pitch fail-safe |
| `/qr` | QR for the Hosting URL |

The view is chosen by the session's `module` field: **focusDesk** → Focus block timeline (HR + fade
score + fade catches + recap), **visionPvt** / **kineticClock** → the trial lab HUD. An unrecognized
`module` renders an explicit "unsupported module" card — it is never silently shown as another
module's data.

## Firestore fields read

Session doc: `athleteId`, `module`, `startedAt`, `status`, `clockOffsetMs`, `clockRttMs`,
`baselineGapMs`, `baselineStdMs`, `breakPointTrial`, `lastHeartRate*`, and for Focus
`focusFocusedSeconds`, `focusBreakSeconds`, `focusFadeCount`, `focusMeanHrBpm`,
`focusExtendedOnce`, `focusBaselineReady`.

`sessions/{id}/epochs/{index}` (Focus, one per 30 s): `index`, `phase`, `remainingMs`, `fadeScore`,
`hrBpm`, `arousalIndex`, `motionEnergy`, `fadeSuggested`.
`sessions/{id}/trials/{index}` (+ `gaze/window`) for the lab modules.

Schema: [`../docs/SCHEMA.md`](../docs/SCHEMA.md) · types: `src/types/session.ts`.

## Reading a fade score

Every term in the composite rests at 0 and only approaches 1 when genuinely faded, so a calm block
sits between about 0 and 0.1 — the fade track is scaled to the session rather than to a fixed 0…1.
The HR term carries a small negative allowance (≈5 bpm under the anchor), so the score can dip below
zero; the axis makes room for that and draws zero as a solid line.

`baselineStdMs` is the raw window σ, but the phone trips on `mean + 2 · max(σ, 0.05)`, so the trip
line applies the same floor. The HR anchor, the arousal baseline and each channel's state are not in
Firestore — they are estimated off the epoch stream with the detector's own rules and labelled as
estimates in the UI.

**Dropped channels.** A channel that is missing, or that carried no usable signal at calibration
(σ(`eyeWide`) under the 0.010 noise floor), drops out and the remaining weights renormalise. The
inputs panel shows that as a hatched track, a struck-through weight and `no term` — deliberately not
as a zero contribution, which is a live channel reporting no fade.

## Demo data

The Focus block is generated by `src/data/focusFadeModel.js`, an executable mirror of
`FocusFadeDetector` (deferred calibration, median HR anchor with downward tracking, z-scored arousal,
two-sample debounce, 90 s cooldown, baseline rescored on `reseed`). Canned desk signals are run
through it one 8 s sample at a time and the 30 s epochs are collected — nothing about the trace is
authored directly, so the catches land where the detector puts them.

`node scripts/seedDemoRest.mjs` seeds `demo-focus-001` (focusDesk, 35 epochs, 2 fade catches) from
that same simulation, plus `demo-session-001` (visionPvt) and `demo-kinetic-001` (kineticClock),
through the Firestore REST API using a `gcloud` token. `/demo/focus` and the seeded session are
therefore the same block; the model is the single source, so they cannot drift.

Hosting: https://synapse-clinical-hz.web.app · QR: `/qr`. Demo mode works offline.

Firebase root files (`firebase.json`, `firestore.rules`, `.firebaserc`) are web-owned; iOS owns
`GoogleService-Info.plist`. See MASTER §9–§10.
